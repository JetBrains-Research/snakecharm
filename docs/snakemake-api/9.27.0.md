# Snakemake 9.9.0 → 9.27.0 (and `main`) API update

Report for the update that moved `defaultVersion` from 9.9.0 to 9.27.0 (branch
`features/snakemake-9.27-api-support`, plugin changelog section `[2026.3.2]`). For the procedure, see
[the update guide](README.md).

Compared sources: snakemake tags `v9.9.0`, `v9.27.0` and `main` at
`4523356973a83aa237a121717ee81dd2e09175da` (2026-10-11). `main` contains the breaking
`feat!: generic software deployment plugin support` (#3339), so its next release is expected to be **10.0.0**.

Status: implemented by static analysis of the snakemake sources, verified on the 263 EAP with
`./gradlew cleanTest test`: full suite green with the default fixture at `main`
`4523356973a8` (3468 tests); the changed features green with the fixture at `v9.27.0`.

## Regressions: API moved, static analysis broke

These broke existing features. They are the likely cause of the failures on the `snakemake_master`
TeamCity configuration, which mounts snakemake `main` as `testData/MockPackages3/snakemake`.

### `run:` section containers (`input`, `output`, `params`, `log`, `resources`, `wildcards`)

| Version | Location | Resources class |
|---|---|---|
| < 9.0.0 | `snakemake/io.py` | `Resources` |
| 9.0.0 – 9.16.2 | `snakemake/io/__init__.py` | `Resources` |
| 9.16.3 | `snakemake/io/__init__.py` | `ResourceList` |
| 9.17.x | `snakemake/io/container.py` | `ResourceList` |
| ≥ 9.18.0 | `snakemake/iocontainers.py` | `ResourceList` |

`snakemake/io/__init__.py` only imports `Namedlist` under `TYPE_CHECKING` now, so the plugin found
no subclasses and nothing in `run:` or SmkSL placeholders (`"{input}"`) resolved.

Done:
- `SnakemakeNames.SNAKEMAKE_MODULE_NAMES_IO_CONTAINERS` lists all three modules; `WILDCARDS_ACCESSOR_CLASSES`
  is derived from it ([SnakemakeNames.kt](../../src/main/kotlin/com/jetbrains/snakecharm/lang/SnakemakeNames.kt)).
- `SnakemakeApi.SECTION_ACCESSOR_CLASSES` is generated per module, including `ResourceList` → `resources`
  ([SnakemakeApi.kt](../../src/main/kotlin/com/jetbrains/snakecharm/codeInsight/SnakemakeApi.kt)).
- `SmkImplicitPySymbolsProvider` collects `Namedlist` subclasses from each module
  ([SmkImplicitPySymbolsProvider.kt](../../src/main/kotlin/com/jetbrains/snakecharm/codeInsight/SmkImplicitPySymbolsProvider.kt)).
- `SmkTypeProvider` (wildcards type in `run:`) and `SmkSLUndeclaredSectionInspection` (module check)
  use the new lists.

### `rules`, `scatter`, `gather`, `simplify_path` and `min_version` on `main`

`snakemake/common/__init__.py` is empty on `main`; the classes are in `snakemake/common/misc.py`.
`snakemake/utils.py` became a package and only re-exports `simplify_path`, `min_version`, ... from
`utils/misc.py` inside `if sys.version_info >= (3, 11):`. The provider's lookup of top-level functions in
`snakemake/utils/__init__.py` doesn't see these re-exports.

Done:
- `SnakemakeApi.GLOBAL_VARS_TO_CLASS_FQN` maps each global to a **list of FQN candidates** (legacy
  location first); the provider uses the first that resolves.
- `snakemake.utils.misc` → `simplify_path` added next to the legacy `snakemake.utils` entry.
- `SmkMinVersionWarningInspection` accepts both `snakemake.utils.min_version` and
  `snakemake.utils.misc.min_version` (`SnakemakeNames.SNAKEMAKE_FQNS_FUN_MIN_VERSION`). With a Python ≥ 3.11
  interpreter, `from snakemake.utils import min_version` resolves to `utils/misc.py`, so the inspection
  silently stopped working.

## New features

### `pathvars` (9.12.0)

```python
pathvars:
    per="{sample}"

rule a:
    output: "<results>/processed/<per>.txt"
    pathvars: results="custom"

module other:
    snakefile: "other/Snakefile"
    pathvars: results="results/other"
```

All three forms take keyword arguments only (`Workflow.register_pathvars(**items)`, `rule_pathvars(**items)`,
`module(pathvars=dict(...))`).

Done:
- `snakemake_api.yaml`: `pathvars` introduced in 9.12.0 for `top-level`, `rule-like` (covers `use`) and
  `module`. The rule-like entry has `placeholders_injection_allowed: False`, so `"{sample}"` in values
  is not checked as an undefined wildcard of the rule.
- `SnakemakeNames.WORKFLOW_PATHVARS_KEYWORD`, added to `SnakemakeApi.TOPLEVEL_ARGS_SECTION_KEYWORDS`
  (the lexer needs top-level keywords hardcoded).

Not done:
- `<name>` placeholders in input/output/log/benchmark strings: no completion, resolve, or validation
  against the default pathvars (`results`, `stats`, `reports`, `temp`, `resources`, `logs`, `benchmarks`)
  and declared ones. Wildcard analysis treats them as plain text, so `"<per>"` where `per="{sample}"`
  hides the `sample` wildcard from the plugin.
- No "positional arguments not allowed" check: the yaml format has no keyword-only flag.

### Callable `priority` (9.17.0)

`priority: lambda wildcards, input: input.size_mb` (`Rule.expand_priority()` passes `input`, `attempt`,
`rulename`). Done as a 9.17.0 `override` of `priority` with
`lambda_args: [wildcards, input, attempt, rulename]`. Before 9.17.0 a callable is still reported by
`SmkSectionUnexpectedCallableArgsInspection`.

### Semantic helpers (9.20.0 – 9.22.0)

| Function | Version | File |
|---|---|---|
| `as_py_module` | 9.20.0 | `ioutils/as_py_module.py` |
| `prepend_param` | 9.21.0 | `ioutils/prepend_param.py` |
| `choose_file`, `choose_folder`, `choose_tmp` | 9.22.0 | `ioutils/choose_f.py` |

`as_py_module` and `prepend_param` were already found, because the provider collects a function named like its
`ioutils/<name>.py` module. `choose_*` are not named after their module, so they were missed, and so
were `parse_input`, `extract_checksum`, `flatten` (`ioutils/input.py`).

Done:
- `collectFunctionsRegisteredInGlobals()` reads the dict literal in `snakemake.ioutils.register_in_globals`
  and resolves each value that names a function (locally or via `from ... import ...`). Calls like
  `rule_item_factory("input")` are skipped, so top-level `input` still resolves to the builtin. Names
  already collected are skipped, keeping single resolve targets.
- `snakemake_api.yaml` introduces all five by FQN with `docs_url`.

### `access` global (9.1.0)

`_globals["access"] = AccessPatternFactory` was never in our globals. Added to `GLOBAL_VARS_TO_CLASS_FQN`
(`snakemake.io.flags.access_patterns.AccessPatternFactory`).

### `software:` directive (`main`, expected 10.0.0)

```python
rule a:
    software: conda(envfile="envs/x.yaml", within=container(image="ubuntu:22.04"))
```

Done: the `software` rule-like section, introduced in `10.0.0`. At the 9.27.0 default it is
reported as added in 10.0.0.

Not done: the factory functions (`conda`, `container`, `envmodules`, ...) are registered at runtime by
software deployment plugins (`SoftwareDeploymentManager.register_in_global_variables`) and remain
unresolved references. The `10.0.0` version is a guess; rename it in the yaml, the mock directory and the tests
if the release differs.

## No change needed

- **Docstrings in `use rule ... with:`** (9.11.0): `SmkStatementParsing` already skips a docstring there.
- **`subpath(with_suffix=...)`** (9.20.0), **`lookup` positional query/dpath** (9.25.0), **`branch` cases with
  `otherwise`** (9.24.0): signatures come from the snakemake sources.
- **`cache: omit-software`** as a per-rule value (9.17.0), **`notebook:` with `pathlib.Path`** (9.14.0): runtime only.
- **New `onstart`/`onsuccess`/`onerror` globals in `workflow.py`** (9.17.0): internal.

## Known gaps / follow-ups

- **`module_name.onstart()`** (9.17.0, `use` modules expose handlers): module names are not implicit
  symbols (see the `TODO` in `SmkImplicitPySymbolsProvider`).
- **Over-collected `snakemake.io` functions**: every top-level function is offered as a global, now including
  the internal `check` (9.27.0). The real namespace is the `from snakemake.io import (...)` list in
  `workflow.py` (`TODO 1` in the provider).
- **Pathvar placeholders**, see above.
- **`software:` factories**, see above.
